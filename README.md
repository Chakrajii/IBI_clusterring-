## 1. Project Overview

This mini-project investigates whether a pair potential learned from a target particle configuration can reproduce its radial distribution function (RDF) when the simulation starts from a random configuration.

The workflow is:

1. Construct a target configuration of 50 particles arranged in a compact cluster.
2. Calculate and save its target RDF, \(g^*(r)\), as a CSV file.
3. Estimate an initial pair potential using the low-density approximation.
4. Initialize a separate simulation with a random valid particle configuration.
5. Run Metropolis Monte Carlo (MC) using the current potential.
6. Update the potential using Iterative Boltzmann Inversion.
7. Repeat the MC/IBI cycle and compare the final RDF and potential against the target references.

**Research question:** Can IBI recover the target pair structure when starting from a random initial configuration?

This is a structural-reconstruction experiment. Recovering the RDF does not guarantee recovery of the exact target coordinates or a unique microscopic potential.

### Grid and excluded volume

The grid coordinates are multiples of 0.1 in each dimension. A particle center may occupy a grid point only if it is inside the box and at least 2.0 units from every other particle center. This is a hard-core exclusion constraint.

The grid is a discretization of allowed particle-center positions; the particle radius is not the grid spacing. A 100-unit box with spacing 0.1 has 1000 intervals per axis (choose and document whether coordinates include both endpoints).

**Important:** A cluster with 50 particles of radius 1 can be generated by placing each new particle at an available grid point near an already placed particle, while enforcing the minimum separation. This creates a compact, growth-based cluster; it does not guarantee that every particle has exactly eight neighbors. The phrase “eight surrounding particles” should be interpreted as a local packing intention, not a strict coordination requirement.

## 4. Radial Distribution Function (RDF)

The RDF measures the pair density at distance \(r\), relative to the density expected for an ideal uniform system.

For a 2D system, the area of a circular shell from \(r\) to \(r+\Delta r\) is

\[
\Delta A(r) = \pi\left[(r+\Delta r)^2-r^2\right].
\]

With bin width \(\Delta r=0.1\), count unique particle pairs \(i<j\) whose distances fall in each bin. Normalize using the shell area, number of particles, and number density \(\rho=N/A\). For a homogeneous 2D system, a common estimator is

\[
g(r) = \frac{2\,H(r)}{N\,\rho\,\Delta A(r)},
\]

where \(H(r)\) is the number of unique pairs in the bin and \(A\) is the box area. This normalization assumes a uniform reference density and needs appropriate finite-size and boundary treatment.

Because the target is a compact cluster embedded in a large mostly empty box, its RDF can depend strongly on how density and boundaries are defined. Document the estimator used. A cluster-conditioned RDF or a periodic bulk RDF is not automatically interchangeable with an RDF normalized using the entire empty box.

Save the target RDF as `data/target_rdf.csv`:

```csv
r,g_target
0.05,0.0
0.15,0.0
0.25,0.0
```

These rows illustrate the format only. With hard-core exclusion, bins below 2.0 should have zero pair counts, subject to the chosen distance convention and bin definitions. Use bin centers \(r_k=(k+1/2)\Delta r\).

## 5. Initial Potential from the Low-Density Approximation

Use the target RDF to estimate an initial potential:

\[
g(r) \approx \exp[-\beta u(r)],
\qquad \beta = \frac{1}{k_B T}.
\]

Rearranging gives

\[
u_0(r) = -k_B T\ln g^*(r).
\]

This estimate is exact only in the appropriate low-density limit for a pairwise interaction model. At finite density, correlations include many-body and packing effects, so this is an initial guess rather than a guarantee of the true interaction potential.

### Numerical safeguards

- If \(g^*(r)=0\), the logarithm diverges. Do not evaluate `log(0)`. Treat the hard-core region separately or clip values to a small documented floor for numerical calculations.
- Smooth or regularize noisy RDF bins before taking the logarithm, if necessary.
- Set the potential to a strong repulsion or an explicit hard-core constraint for \(r<2a\).
- Define a cutoff \(r_{\mathrm{cut}}\) and document how the potential is treated beyond it.
- Choose a consistent energy reference, often \(u(r_{\mathrm{cut}})=0\).

Save the initial potential to `data/potential_initial.csv`:

0.15,0.0
0.25,0.0

## 7. Metropolis Monte Carlo

Each MC update proposes moving one randomly selected particle to a nearby grid point or by a random displacement compatible with the grid. Reject any proposal that violates the hard-core constraint.

For a valid proposed move, calculate the potential-energy change:

\[
\Delta U =
\sum_{j\ne i}u(r'_{ij})
-
\sum_{j\ne i}u(r_{ij}).
\]

Accept the move with probability

\[
P_{\mathrm{acc}} = \min\left(1,e^{-\beta\Delta U}\right).
\]

If rejected, retain the old position. Use the same potential interpolation, boundary conditions, cutoff, and hard-core rules throughout the run.

**Definition for this project:** one MC iteration = 500 attempted MC updates. Record the acceptance ratio. If almost all moves are rejected or accepted, tune the proposal size while keeping the physical model unchanged.

### MC/IBI schedule

The requested schedule is interpreted as follows:

1. Run 1 MC iteration (500 attempted updates) using the initial potential \(u_0(r)\).
2. Calculate the sampled RDF \(g_0(r)\), then perform IBI update 1.
3. Run 20 MC iterations (10,000 attempted updates) using the updated potential, calculate the RDF, then perform IBI update 2.
4. Repeat the 20-iteration block before each subsequent update.
5. Perform 11 potential updates in total.

This schedule gives one initial iteration before the first update, followed by ten 20-iteration blocks before updates 2–11: 201 MC iterations in total, or 100,500 attempted updates, assuming the initial iteration is not repeated. Clearly record the actual schedule in the output metadata. The first 500-update sample may be far from equilibrium; consider equilibration and sampling quality when interpreting results.

## 8. Iterative Boltzmann Inversion (IBI)

Use the update shown in the project reference:

\[
u_{n+1}(r_i)
=
u_n(r_i)
+
k_B T\ln\left[
\frac{g_n(r_i)}{g^*(r_i)}
\right],
\]

where:

- \(u_n(r_i)\) is the current potential at distance bin \(r_i\),
- \(g_n(r_i)\) is the RDF measured in the current MC sample,
- \(g^*(r_i)\) is the target RDF,
- \(T\) is held fixed.

The measured RDF must be the numerator and the target RDF the denominator for this sign convention. If \(g_n(r)>g^*(r)\), the update raises the potential at that distance, discouraging excess pairs there.

### Stabilization

RDF bins may have zero counts, particularly in a sparse system. Direct logarithms can therefore be undefined or divergent. Use documented regularization, for example

\[
u_{n+1}(r)
=
u_n(r)
+
\alpha k_B T
\ln\left[
\frac{\max(g_n(r),\varepsilon)}
{\max(g^*(r),\varepsilon)}
\right],
\]

where \(0<\alpha\leq1\) is a damping factor and \(\varepsilon>0\) is a small floor. This is a stabilized variant of the reference update. Record \(\alpha\) and \(\varepsilon\) in the run configuration.

Do not allow IBI to remove the hard-core exclusion. Handle forbidden distances explicitly, and avoid updating bins where the target has no reliable statistical information. Consider smoothing the update and enforcing a consistent cutoff.

After every update, save the potential and the RDF used to compute it. This allows the full convergence history to be inspected.

## 12. Reproducibility and Validation

- Set and record random seeds.
- Verify that all particle separations satisfy the hard-core constraint.
- Test the RDF normalization on a known uniform random configuration.
- Check that the pair-energy sum counts each pair once.
- Verify the sign of the IBI update with a simple test: excess sampled pairs at a distance should increase the potential there.
- Save the potential and RDF at every update.
- Check sensitivity to bin width, RDF smoothing, MC duration, damping factor, and random seed.
- Run multiple random starting configurations before making a strong claim about convergence.

## 13. Limitations and Interpretation

This project tests whether an IBI-derived effective pair potential can reproduce a chosen target RDF under a specified simulation protocol. It does **not** prove that the exact target coordinates can be recovered, nor that the inferred potential is unique.

Several factors can make convergence difficult:

- The target is a finite cluster, not a homogeneous bulk fluid.
- Standard RDF normalization assumes a well-defined reference density and geometry.
- The low-density approximation may be inaccurate for a dense cluster.
- A single RDF may not contain enough information to identify a unique potential.
- Short MC blocks may not equilibrate the system after a potential update.
- A hard-core constraint and a grid-restricted move set affect the accessible configurations.

If the main objective is cluster formation, inspect visual snapshots alongside the RDF. You may also track cluster size, radius of gyration, and coordination number. These observables help distinguish a true compact cluster from a configuration whose RDF matches only approximately.
